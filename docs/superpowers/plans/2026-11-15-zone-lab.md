# Zone Lab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Debug-only Zone lab that records spot fingerprints, guesses the current spot, tracks and asks for feedback, and uploads everything to Supabase.

**Architecture:** Models, classifier and event builders in `:core` (`com.habittags.core.zone`), tested locally. Scanner, sensors, screen, tracking service and outbox in `app/src/debug/.../zone`. Uploads reuse `Backend.report`. Analysis in Python against the Management API.

**Spec:** `docs/superpowers/specs/2026-11-15-zone-lab-design.md`

## Global Constraints

- Nothing in `src/main` or `src/release` changes except what's needed to compile both variants.
- Event payloads ≤ 4 KB; ≤ 500 events per `report_events` call.
- Every event has `day`, `tz` (IANA) and `at` (UTC ISO-8601).

## Review Focus

1. Scan throttled (startScan false) → recording waits and retries, never stores stale scans as fresh.
2. Huge Wi-Fi list (100+ APs) → payload trimmed under 4 KB.
3. Outbox > 500 events → sent in chunks; a failed chunk stays queued.
4. No recordings yet → "Where am I?" says so instead of crashing.
5. Location services off / permission denied → clear message.
