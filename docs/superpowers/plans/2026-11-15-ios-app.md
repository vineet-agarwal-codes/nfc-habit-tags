# iOS App (Soft Launch) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A SwiftUI iPhone app with the Android app's behaviour minus app blocking, testable by Vineet's friends through TestFlight.

**Architecture:** `ios/` holds a SwiftUI app that links the shared Kotlin Multiplatform `:core` as `HabitCore.xcframework`, which Gradle builds on the macOS runner. Swift owns only the platform pieces: UI, CoreNFC, Universal Links, local notifications, background tasks, HTTP/WebSocket and file storage. Every rule (recipes, params, time windows, modes, gate, catalog merge/order, usage reports, realtime messages) comes from `:core`, with no Swift copies. CI is GitHub Actions `macos-15`. TestFlight upload runs only when App Store Connect secrets exist.

**Tech Stack:** Swift 5.10 / SwiftUI, iOS 16+, Xcode 16, XcodeGen (project from `ios/project.yml`), Kotlin 2.0 KMP (`assembleHabitCoreXCFramework`), URLSession + URLSessionWebSocketTask, CoreNFC, UserNotifications, BackgroundTasks, XCTest/XCUITest, Maestro (iOS simulator), fastlane `pilot`.

**Spec:** `docs/superpowers/specs/2026-11-14-nfc-habit-tags-design.md`, `2026-11-15-discover-and-stats-design.md`, `2026-11-15-manual-start-design.md` (iOS sections and decisions). The Android app under `android/app` is the behavioural reference.

## Global Constraints

- Bundle id `com.habittags.app`; display name "Habit Tags"; iOS 16.0 minimum; iPhone only.
- **Soft launch without blocking:** `blockGroups` actions are kept in the mode state, but the UI shows "App blocking — coming soon on iPhone". No FamilyControls code ships in this plan.
- DND/Focus can't be set by apps. `dnd` actions show "Turn on Focus yourself, or add our Shortcut" with a link to a documented Shortcut recipe in `ios/README.md`. No code beyond that link.
- Tag URL record: `https://vineet-agarwal-codes.github.io/t/<tagId>` (tagId = `TagPayload.newTagId()`, 22 chars base64url). The app also accepts Android tags (external type `com.habittags.app:tag`) when scanned in-app, and offers "Rewrite for iPhone".
- Universal Links: associated domain `applinks:vineet-agarwal-codes.github.io`. The AASA file lives in Vineet's user Pages repo `vineet-agarwal-codes.github.io` at `/.well-known/apple-app-site-association` with `appIDs: ["<TEAM_ID>.com.habittags.app"]` and `components: [{"/": "/t/*"}]`.
- Supabase URL and publishable key are the ones already shipped in the Android app (public). No secrets in the repo; signing and App Store Connect keys exist only as GitHub secrets.
- State is persisted with `StateCodec` JSON in the app's Application Support directory, using an atomic write. A corrupt file is moved aside (same rule as Android).
- Time handling follows core: instants in UTC, tap log entries carry the IANA zone, recipe windows are wall-clock.
- Debug-only test hooks (`habittags-debug://` links: tap, fixture backend, gate words, param) are compiled only under `#if DEBUG`.

## Review Focus

1. **App killed while a mode is on, then auto-off passes.** On next launch or foreground, `ModeEngine.expire` ends the mode and runs end actions once. The scheduled local notification has already told the user. (Task 4 XCTest `expireOnLaunch`.)
2. **Tag tapped from the lock screen with the app not running** → Universal Link cold start → the tap runs exactly once. (Task 6 UITest via `simctl openurl` on a terminated app.)
3. **An Android-written tag scanned on iPhone** → recognised, and "Rewrite for iPhone" is offered. (Task 6 unit test on NDEF parsing.)
4. **Bulk insert in the gate** (paste, dictation, QuickType suggestion) → rejected. Typing a character at a time completes it. (Task 5 XCTest on the text view delegate.)
5. **Offline first launch** → bundled catalog shown, no crash, report queued. (Task 3 UITest with a fixture "offline" flag.)

### Task 3: Backend, catalog, Discover / My recipes / recipe screens

**Files:** `Backend/SupabaseClient.swift`, `CatalogRepository.swift`, `RealtimeWatcher.swift`, `UsageReporter.swift`. `UI/DiscoverView.swift`, `MyRecipesView.swift`, `RecipeView.swift`, `InstallFlow.swift`, `EditView.swift`, `ParamControls.swift`, `ActiveStrip.swift`. Tests: `CatalogRepositoryTests`, UI tests.

**Interfaces:**
- Consumes: `decodeRemoteCatalog`, `mergeCatalog`, `withoutInvalidRecipes`, `discoverOrder`, `statLabel`, `Realtime.*`, `buildReport`, `reportDue`, `afterReportSent`, `mergeParams`.
- Produces:
  - `protocol Backend { func fetchCatalog() async throws -> CatalogSnapshot; func report(deviceId: String, events: [UsageEvent]) async throws }`, with `SupabaseBackend` (same three GETs and RPC as Android's `SupabaseBackend`) and `FixtureBackend` (DEBUG).

  - `UsageReporter`: `BGAppRefreshTask` id `com.habittags.app.report` every 6 h, plus on-open when `reportDue`. Requests are serialised (an actor).
  - UI behaves like the Android screens: the tab bar has Discover (not installed, `discoverOrder`) and My recipes; the recipe page shows stats lines and "Turns on between…"; install runs params (sliders, and a `DatePicker(.hourAndMinute)` for `time` params) → "Write to a tag" or "Skip for now"; Edit offers params, tags, write another, uninstall. ### Task 4: Modes — tap handling, Start now, active strip, effects

**Files:** `Modes/TapHandler.swift`, `Modes/EffectRunner.swift`, `UI/ChecklistView.swift`. Tests: `TapHandlerTests`.

**Interfaces:**
- Consumes: `ModeEngine.onTap/startManually(force:)/expire/endViaGate/modeKey`, `TapResult` (all cases including `OutsideHours`, `AlreadyOn`, `StrictRefused`).
- Produces: `enum TapHandler { static func handleTag(_ tagId: String, model: AppModel) -> TapResult; static func startManually(recipeId: String, force: Bool, model: AppModel) -> TapResult }`. These log taps with `source` "tag" or "app" and the IANA zone, run effects, schedule or cancel the auto-off notification, and show a banner message. Their text matches the Android `TapHandler` copy, including `outsideHoursMessage`.
- `EffectRunner`: `Checklist` → sheet; `Timer` → local notification; `OpenApp` → `UIApplication.open(uri)` when `uri` is set, otherwise skipped; `Log` → tap log.
- Start now behaves as on Android: `OutsideHours` → alert "Outside its usual hours" with Start anyway (`force: true`) and Cancel.

- [ ] **Step 1:** XCTest: `expireOnLaunch` (mode with a past `autoOffAt` ends at launch and its end actions run once); Start now outside the window returns `OutsideHours`, and force starts the mode; strict refusal message.

### Task 5: Typing gate

**Files:** `UI/GateView.swift`, `UI/GateTextView.swift` (a `UIViewRepresentable` around `UITextView`). Tests: `GateTextViewTests`.

**Interfaces:**
- Consumes: `FrictionGate.passage/acceptEdit/matchedLength/hasTypo/wordsTyped/wordCount/isComplete`, `ModeEngine.endViaGate`.
- Produces: the same layout as Android's GateScreen: title "End <label> early?", the instruction line, "N of M words" with a progress bar, the passage with typed text green and the next letter highlighted (red on a typo), and an outlined "Start typing here…" box that becomes first responder on appear.
- `GateTextView`: `autocorrectionType = .no`, `spellCheckingType = .no`, `smartInsertDeleteType = .no`, `textContentType = nil`, `canPerformAction` returns false for paste and its variants, `shouldChangeTextIn` rejects any replacement longer than `FrictionGate.MAX_INSERT` characters (this covers dictation and QuickType), and dictation is disabled through `keyboardType = .asciiCapable` where possible.

- [ ] **Step 1:** XCTest: inserting "abcdef" is rejected, "abc" is accepted, `canPerformAction(paste)` is false, and the completion callback fires on the full passage.

### Task 6: NFC write/read and Universal Links

**Files:** `NFC/TagSession.swift`, `NFC/TapRouter.swift`, entitlements in `project.yml`. Modify `android/core/.../tag/TagPayload.kt`, plus `android/app` intent filter. Tests: `TagPayloadTest` (core), `TapRouterTests`, UITest `coldStartTagLink`.

**Interfaces:**
- Core: `TagPayload.urlFor(tagId: String): String` = `"https://vineet-agarwal-codes.github.io/t/$tagId"`, and `TagPayload.parseUrl(url: String): String?` (accepts only that host, path `/t/<valid id>`).
- Swift:
  - `TagSession.write(tagId:) async throws` uses `NFCNDEFReaderSession`, writes a single URI record, and checks capacity and lock status. Errors map to "This tag is locked", "Tag too small", and "Hold the phone still near the tag".
  - `TagSession.read() async throws -> String`: reads the URL record, or the Android external record (then flags `needsRewrite`).
  - `TapRouter.handle(url:)`: a Universal Link → `TapHandler.handleTag`. An unknown tagId → "Set up this tag" picker. A DEBUG `habittags-debug://` link → test hooks.
- Info.plist: `NFCReaderUsageDescription`. Entitlements: `com.apple.developer.nfc.readersession.formats = [NDEF, TAG]`, `com.apple.developer.associated-domains = [applinks:vineet-agarwal-codes.github.io]`.
- Android: add an `NDEF_DISCOVERED` filter for `https://vineet-agarwal-codes.github.io/t/` so iPhone-written tags also work on Android. `TapActivity` uses `TagPayload.parseUrl`.

- [ ] **Step 1:** Core table tests for `urlFor`/`parseUrl`: a valid URL, the wrong host, a bad id, and a trailing slash.
- [ ] **Step 2:** Implement. UITest `coldStartTagLink`: terminate the app, run `simctl openurl` with a fixture tag URL (DEBUG setting lets an https link map through `TapRouter`), and assert the "On now" strip. NFC hardware itself is checked only on device.
- [ ] **Step 3:** CI green for both workflows. Commit.
